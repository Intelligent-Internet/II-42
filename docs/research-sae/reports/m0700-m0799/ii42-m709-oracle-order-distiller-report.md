# M709 Oracle-Order Distiller Report

M709 tested whether M704's safe-fill oracle can be learned by changing the
supervision from binary target membership to an oracle-order regression target.

This remains a first-stage dense-equivalence probe:

- no BM25
- no reranker
- no qrels loss
- no native reranking sweep
- no learned gate

## Context

The route before M709:

| Version | Finding |
| --- | --- |
| M704 | Oracle budgeted set selection is strong: `0.541176 -> 0.617647`, fixed/regressed `234/0` |
| M706 | Learned pointwise selector misses target coverage: b384 recall `0.701639` vs oracle `0.982671` |
| M707 | Query-conditioned/risk model is worse: b384 recall `0.596205` |
| M708 | Simple feature orderings are worse: b384 recall `0.537679` |

M709 asks whether an oracle-order/listwise target can recover the missing target
coverage with the same candidate feature space.

## Method

For every query candidate atom, M709 creates a continuous target:

- target atoms get a high base score;
- early M704 safe-fill oracle ranks get additional rank bonus;
- target impact magnitude adds a bounded bonus;
- negative-only atoms get a small negative score.

Two regressors are trained:

- `raw`: current atom features
- `conditioned`: raw features plus query-normalized features

The output is ranked by predicted oracle-order score. Evaluation is target
coverage only; native ranking is skipped unless the coverage gate passes.

## Run

## Interpretation

M709 rules out a second simple explanation.

The failure is not just that M705 used binary target labels. Replacing that
with a continuous oracle-order target does not recover the missing coverage.

The target atoms are visible, and M704 can safely use them. However, the current
candidate feature space cannot rank enough of them into the budget, even when
trained directly against the oracle order.

## Decision

Do not scale M709 or run native reranking.

The next useful work should change the input representation or supervision
source, not just the loss target:

1. Add source-document interaction features that explain why an atom is useful
   for the dense-boundary pair.
2. Train from query text/dense-root output to generated postings, rather than
   selecting from scalar candidate features alone.
3. If staying with selection, use pair-impact examples generated by actual
   native score deltas, not only oracle target membership/order.

M704 remains a valid upper-bound signal. M709 shows the current selector input
is under-specified.
