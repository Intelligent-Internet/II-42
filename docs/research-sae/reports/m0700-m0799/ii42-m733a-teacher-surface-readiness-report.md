## Summary

M733A should proceed as a small source-aware fixed-delta native canary, not as
a deep compiler training run.

The key reason is that prior evidence separates the bottleneck clearly:

- M684/M685 already tested query-level selector and candidate-doc atom copying.
  Both had useful classifier signal, but neither produced a safe Recall/MAP
  lift.
- M686 showed atom-level deltas have real signal, but still need better
  admission and source-aware interface control.
- M697 showed source-aware support atom budgets can recover the M691/M683-style
  target atoms: `support_atoms384` reaches `0.883929` atom visibility.
- M699 showed the dense-boundary version is still only partially ready:
  `support_atoms384` reaches `0.711400` visibility and only `0.012531`
  full-hit share, so deep training is premature.
- M727/M728 rule out the easy explanation that this is just under-training.

## Decision

Proceed with:

`M733A source-aware fixed-delta native canary`

Design constraints:

- Use frozen `P1.3 / M549U native signed-dot` document/index geometry.
- Start from the M697 `support_atoms384` source-aware atom interface.
- Use a fixed small delta family first, not arbitrary vector generation.
- Use protected head atoms and dense/P1 support risk as hard features/gates.
- Train at most a small global selector/admission model.
- No dataset-specific tuning.
- No plain reranker output.

Canary surface:

`fiqa,arguana,scidocs,cqadupstack`

Promotion gates:

- `Recall@100 >= P1`
- `MAP@100 >= P1`
- `O@100 >= P1`
- `O@256` no material regression
- `CUB >= P1`
- no material NDCG@10/MRR@20 regression

Do not expand to shared15 unless the canary passes these gates.
