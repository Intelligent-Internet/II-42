# SAE Full-BEIR Shared-Teacher Training Report

## Scope

This pass re-ran the text-to-sparse-atoms training line with broader and more
defensible supervision:

- all 15 locally cached BEIR datasets with qrels;
- one shared SAE teacher across datasets, instead of per-dataset teachers;
- 10k unlabeled commons records from elm arxiv/pubmed as domain text for the
  shared teacher only;
- qrels-aware evaluation grids for the student atom score weight.

The goal was to answer whether broader BEIR quality labels and unlabeled
commons text improve the text-to-atoms route enough to reduce or remove the
serving-time dense embedding dependency.

## Why The Shared Teacher Matters

Earlier text-to-atoms runs used sampled BEIR data, but the teacher atoms were
generated by separate SAE teachers per dataset. That made atom ids local to each
dataset. A student trained across those labels was therefore asked to learn
inconsistent latent ids.

This run fixes that by building a single `shared_sae_8192_64` teacher over all
sampled BEIR documents plus unlabeled commons domain text. The same atom id now
has one global meaning across all training and evaluation datasets.

## Implementation Notes

New shared-teacher builder:

```text
scripts/research_sae_build_shared_teacher.py
```

The builder:

- prepares BEIR qrels-preserving samples;
- reuses cached Snowflake embeddings when present;
- trains one global TopK SAE teacher;
- writes per-dataset document/query latents under the shared teacher id;
- accepts unlabeled JSONL rows with optional precomputed embeddings.
- writes unlabeled teacher latents so product-domain text can be used for
  optional doc-side student distillation.

The unlabeled loader now accepts both normal NDJSON and PostgreSQL `COPY` text
format JSON. This was necessary because `COPY ... TO STDOUT` escapes JSON
backslashes again, turning JSON quote escapes into invalid raw NDJSON unless the
COPY text escape layer is folded once.

The embedding exporter now clips long text and caps model sequence length. This
prevents long StackExchange/abstract rows from creating pathological MPS
attention buffers during embedding export.

## Findings

The broader shared-teacher route is materially better than the earlier
five-dataset/per-dataset teacher route. The old sampled frontier was roughly
Recall@100 `0.7735` and MRR@20 `0.6483` on the narrower matrix. The new
full15 shared-teacher matrix reaches Recall@100 `0.8240-0.8254` and MRR@20
`0.8231` on the broader qrels-preserving matrix.

The best balanced run is:

```text
results/sae/text-atoms/full15-shared-dense-teacher-token-char/
```

It improves over BM25 by:

- Recall@100: `+0.0402`;
- MRR@20: `+0.0368`;
- NDCG@10: `+0.0436`;
- MAP@100: `+0.0573`.

It still trails the dense-derived SAE teacher by:

- Recall@100: `-0.0185`;
- MRR@20: `-0.0227`;
- NDCG@10: `-0.0396`;
- MAP@100: `-0.0422`.

Increasing the pair budget improves Recall@100 slightly (`0.8254`) but hurts
MRR/NDCG/MAP. This suggests larger pair budgets open more semantically relevant
documents but also over-pull lower-confidence matches into the head of the
ranking.

Coverage loss is mechanically valid and converges, but it does not beat the
dense-pair frontier. It is useful research infrastructure, not the current
default.

Commons unlabeled student distillation is not a default yet. Using all 10k
unlabeled rows directly reduces the BEIR matrix; using a 2k subset is closer,
but still trails the pure BEIR dense-pair run. The most likely reason is that
unweighted doc-side product-domain mimicry changes the student atom prior
without adding query-side relevance supervision. For now, arxiv/pubmed unlabeled
data is useful for shared teacher/domain atom formation, but student-side use
needs weighting, curriculum, or pseudo-query supervision.

Listwise dense-teacher distribution matching again underperforms. The listwise
loss does not consistently decrease, which matches the earlier result that
static soft distribution matching is weaker than pairwise dense-teacher
coverage for this candidate-generation task.

The best global student weight is usually around `0.5-0.75`. Higher weights
often preserve recall but damage first-page ranking, especially at `1.5`.

## Current Decision

Promote the full15 shared-teacher data path as the new text-to-atoms research
baseline.

Do not productize the text-only student as a dense-teacher replacement yet. The
student is now clearly useful and consistently beats BM25, but it still has a
measurable gap to the Snowflake-derived SAE teacher.

For the next training round, use `full15-shared-dense-teacher-token-char` as the
default starting point and treat `student_sae_weight = 0.5` as the recall/MAP
default, with `0.75` available when optimizing MRR.

## Next Steps

1. Add a qrels-aware calibration layer that chooses `student_sae_weight` from
   query/document diagnostics instead of one global constant.
2. Add a harder candidate-budget loss that directly optimizes opened-document
   coverage under a fixed atom budget.
3. Test a pretrained lexical encoder or SPLADE-style backbone instead of the
   current mean pooled token/char encoder.
4. Revisit arxiv/pubmed student use through pseudo queries, dense-neighborhood
   anchors, or a low-weight curriculum. Direct unweighted doc-side distillation
   is not enough.
5. Run a full-corpus BEIR validation only after the training frontier improves
   enough to justify the cost.
